# v0.5.0 — Keep monitoring while offline

Your monitor can now keep collecting readings when Wi-Fi or the monitoring
service is unavailable, then send them when the connection returns. An optional
SD card provides much more room for those offline readings.

## What's new

- **More room for offline readings.** A compatible SD card is detected at startup
  and used automatically. Without one, the monitor uses its built-in storage.
  Readings are stored in groups to use the card efficiently, with a limited
  amount kept in memory for sending.
- **Monitoring starts without an internet connection.** Previously enrolled
  devices use their saved monitor settings and continue scheduled checks,
  including Bluetooth collection. Checks that need a network still depend on
  that network being available.
- **Automatic connection recovery.** The device retries Wi-Fi after a router
  outage or an unsuccessful startup connection. Retries become less frequent
  during an extended outage to reduce unnecessary connection attempts.
- **Better timestamps after an offline start.** The device remembers its last
  saved time. When internet time becomes available, it briefly pauses to correct
  affected readings before sending them. Previously verified reading times are
  preserved, and an interrupted correction can resume after a restart.
- **Clearer RGB status lights.** On supported boards, the light shows startup,
  connection and time-sync progress. A brief green flash marks a monitor check;
  a brief blue flash marks a data batch sent for delivery. Amber indicates a
  connection outage, and fast cyan indicates the timestamp-correction pause.
- **Storage protection and useful diagnostics.** The device checks available
  space and pauses new readings before storage fills. It keeps retrying delivery
  so acknowledged readings can free space. Logs report remaining space and an
  estimated offline recording duration when enough information is available.
- **Updated dependencies.** This release includes updated compression and
  quantum-TLS libraries, alongside build and documentation improvements.

## Before updating

Your enrollment, Wi-Fi settings and monitor configuration are retained by an
ordinary OTA update. **Existing unsent readings are discarded when first moving
to the new storage system.** Let the device finish sending its backlog before
updating if those readings matter to you. Changing between SD and built-in
storage at a later startup also discards the previous store's unsent readings;
there is no automatic transfer between them.

The SD card must already be formatted and connected correctly; the firmware
never formats it automatically. Keep it inserted while the device is running.
A card or storage error pauses new readings rather than silently abandoning the
backlog. See the [SD wiring and storage guide](https://github.com/Mungert69/NetworkMonitorProcessorAgentEmbedded/blob/v0.5.0/docs/offline-storage.md)
and [RGB light guide](https://github.com/Mungert69/NetworkMonitorProcessorAgentEmbedded/blob/v0.5.0/docs/guide.md#boot-router-recovery-and-rgb-indicator).

## Timing and recovery limits

Sending waits for a successful internet-time check and completion of any time
correction during each startup. Normal time synchronization happens once per
startup; small clock drift during long periods of uninterrupted use is accepted.
Several power outages before any successful time check can leave older readings
with approximate times. A power loss can also lose readings collected since the
last completed save. This is not a replacement for a battery-backed clock.

New readings normally become eligible to send on the next monitoring cycle.
Delivery still requires confirmation from the monitoring service before readings
are removed. Downgrading to older firmware is not a supported way to recover a
backlog stored by this version.

## Validation

All 43 native tests passed with memory/error checks enabled. Tooling checks and
both serial setup/reset emulator tests also passed. The signed firmware built
successfully and its signature and download checksum were verified.

The new monitoring code was tested on an ESP32-S3 with an SD card: offline
readings survived a restart and were acknowledged after reconnection. The time
correction completed before messaging started, followed by a successful monitoring
cycle and service acknowledgement. Nonzero time corrections and interrupted
rewrites were tested in the host suite; sudden power loss during a physical card
write and OTA rollback were not tested in this release validation.

## Downloads and installation

- Use `networkmonitor-esp32-s3-0.5.0-<sha256>.bin` for OTA updates on an enrolled
  device. Staging or downloading it does not start an update.
- Use `networkmonitor-esp32-s3-live-factory-0.5.0.bin` only for a first installation
  on the supported ESP32-S3 with 16 MB flash and 8 MB PSRAM. Factory installation
  replaces existing device settings and requires Wi-Fi setup and enrollment.
  **Do not use the factory image for OTA.**
- Verify downloads with the attached `SHA256SUMS.txt`.
