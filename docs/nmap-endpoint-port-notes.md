# ESP32 Nmap-compatible endpoint and command-processor notes

Work branch: `feature/esp32-nmap-endpoint` (branched from `main`).

This file is a running handoff note for implementing the ESP32 `nmap` monitor
endpoint. Update it as behavior, tests, or design decisions change.

## Scope and constraints

- Implement the `nmap` monitor endpoint and the bounded `Nmap` command
  processor; `nmapvuln` remains unsupported/disabled.
- Do not copy or vendor Nmap source, NSE scripts, service-probe databases, or
  other Nmap project assets. Implement our own small scanner in C.
- Keep the implementation modular so scanner stages/fingerprints/port coverage
  can be expanded later without changing the monitor/runtime contract.
- Keep resource use bounded for the ESP32-S3: bounded ports, a total deadline,
  bounded diagnostics, and no unbounded socket/task allocation.
- Preserve the .NET endpoint's user-visible up/down intent and `MonitorPingInfo`
  result flow as closely as is sensible; exact Nmap output is not a goal.

## .NET reference inspected

Reference files:

- `~/code/NetworkMonitorLib/Objects/Connection/NmapCmdConnect.cs`
- `~/code/NetworkMonitorLib/Objects/Factory/EndPointTypeFactory.cs`
- `~/code/NetworkMonitorLib/Objects/Connection/Tests/NmapCmdConnectTest.cs`

The .NET `nmap` endpoint queues the `Nmap` command processor with arguments
`-sV --system-dns <address>`; when `MonitorIP.Port != 0`, it adds `-p <port>`.
It sets `IsLongRunning` and extends the monitor timeout by 10x. It treats output
containing `Host is up` as success with status `Port/s open`; output containing
`Host seems down` or `0 hosts up` becomes failure with status `Port/s closed`.
The raw filtered scan output is stored as the result message. `nmapvuln` uses
the same wrapper with `--script vuln` and is explicitly out of scope here.

## Implemented first increment

`firmware/main/endpoint_nmap.c` translates monitor fields into an Nmap-style
argument vector (`nmap -sV --system-dns [-p PORT] TARGET`) and interprets the
runner result. It never invokes a shell. `nmap_runner.h` is the process-like
boundary; `nmap_runner_embedded.c` is the ESP32 implementation and executes the
scan with bounded sockets. That split leaves room for a real binary adapter on
a host platform without changing monitor/result handling.

A configured nonzero port scans only that port. Port zero scans 22
project-owned common TCP ports (not a copied Nmap port/probe database). It
reports open ports with conservative port/service-name hints. Its report is
capped at 32768 bytes and 256 lines; allocation/socket exhaustion returns
`NM_PROBE_LOCAL_FAILURE`. The endpoint layer applies the .NET 10x timeout
extension once; the runner receives that exact total budget. The former
120-second runner ceiling and hidden second extension have been removed.
Common-port connection attempts retain 250 ms slices within the overall budget.
Successful endpoint durations use scale 10; standalone command reports keep
actual elapsed milliseconds. See [the endpoint audit](endpoint-parity-audit.md).

The monitor endpoint result uses the .NET user-facing `Port/s open` /
`Port/s closed` status strings and an Nmap-shaped summary. It does not perform
Nmap's full service-version probes, default top-1000 scan, or produce
byte-identical output. For now a refused TCP connection is positive evidence
that the host is reachable; a silent/firewalled target may be reported down
even if another discovery method could find it. The standalone `Nmap` command
processor has a separate bounded `-sn` ARP/ICMP discovery mode documented below.

The endpoint remains a drop-in at the `nm_esp_endpoint_run()` boundary. The
runner accepts only the argument subset generated by the endpoint; it rejects
arbitrary flags (including vulnerability scripts) and never consumes
`MonitorIP.Args`.

### TCP service-name hints

`firmware/main/service-hints.csv` is embedded as read-only firmware data. It
contains 5,889 TCP service-name assignments for numeric ports 1–49151 from the
IANA Service Name and Transport Protocol Port Number Registry. The runtime
searches the sorted CSV directly in flash and copies only the selected name to
a small stack buffer; it does not allocate an index or load the file into RAM.
The current generated file is about 87 KB.

To refresh it from the current IANA CSV, run
`python3 tools/update-service-hints.py`, review the resulting diff, then rebuild
the firmware. The generator keeps only single TCP port assignments and safe
ASCII names, selects one label for duplicate port assignments, and excludes
the dynamic port range 49152–65535. These are registry labels, not protocol
detection: a service listening on a port can be something else. Nmap's `-sV`
therefore remains a static hint and does not identify the running software.

## External scanner source review (2026-10-02)

Reviewed upstream source and project documentation for design ideas only:

- [Masscan](https://github.com/robertdavidgraham/masscan) separates target and
  port ranges from its transmit/receive engine. Its useful conceptual pattern
  is representing work as a bounded target × port space and iterating it
  through a small scanner contract. Its core scanner is asynchronous
  raw-packet I/O with a user-mode TCP/IP stack; that transport, rate model, and
  scale are not a fit for this ESP-IDF/lwIP implementation. Masscan is AGPL-3.0,
  so do not copy or vendor its implementation into this GPL-3.0 project without
  a deliberate licensing decision.
- [arp-scan](https://github.com/royhills/arp-scan) is a useful focused reference
  for separating option parsing, target selection, link-layer probing, reply
  decoding, and output. Its implementation uses libpcap/raw-link access and is
  GPL-3.0; neither that backend nor its code is needed for the first embedded
  host-discovery feature. Reimplement any needed behavior independently using
  supported ESP-IDF/lwIP APIs.

Implementation decisions for the bounded Nmap-compatible command path:

1. Keep parsing, target planning, scanning, and output bounded. `nmap_targets.*`
   parses a normalized IPv4 range without allocating a host array;
   `nmap_cmd_processor.*` owns option policy; and `nmap_runner.h` separates
   policy from ESP-IDF network operations.
2. `-sn` accepts one host or IPv4 CIDR from `/24` through `/32`; at most 254
   usable addresses are iterated. Local IPv4 uses fresh ARP replies, off-link
   targets use ICMP, sequentially with a shared deadline and 200 ms maximum
   per-host wait. Cancellation is checked during waits. Larger CIDRs are rejected
   before network activity.
3. TCP scans stay on the lwIP nonblocking TCP-connect runner. `--reason` reports
   the observed connect result and `-v`/`-vv` adds a bounded summary (not live
   Nmap progress). `-F` selects an
   eight-port project-owned subset when `-p` is absent. `-Pn` skips discovery
   and assumes the target is up; `--open` filters non-open rows. Host reachability
   without `-Pn` uses local ARP replies and TCP outcomes, not Nmap's full ping-probe set.
   `--system-dns` uses the system resolver already used by this firmware.
4. Reports are bounded to 32768 bytes and 256 lines, sufficient for a full `/24`
   discovery response. The message formatter can paginate the result; the live
   harness requests all lines so it can verify the final scan summary.
5. `-sV` is still only a static service-name hint, not active version
   fingerprinting. NSE, UDP, raw SYN, OS detection, IPv6 CIDR and file output
   remain explicit unsupported options rather than silent approximations.

The live signed MQTT harness is in `tests/integration/nmap_command/`. It checks
the supported command path against a known TCP listener, performs a bounded
same-subnet `/24` `-sn` discovery when given an IPv4 test host, and verifies
that an over-limit `/23` and NSE are rejected. It is deliberately a dev test:
it needs a current private board config/AuthKey and a test service, and must
not use a stale fixture after re-registration. Passing those cases is not
evidence that unsupported Nmap features have been implemented.

## ARP adapter and scanner review

`nmap_arp.*` sends `etharp_request()` on the Wi-Fi station interface through
short `esp_netif_tcpip_exec()` callbacks. A linker wrapper observes valid
fresh ARP replies before forwarding every packet to the original lwIP handler.
It does not replace Wi-Fi callbacks, clear the shared ARP cache, or use libpcap.
One bounded observer is shared. Competing probes join a FIFO and wait outside
the TCP/IP task; the existing total timeout includes admission and packet wait.
Cancelled or expired waiters are removed before their stack is released.
Admission expiry is inconclusive, never a host-down sample. Each subnet target
releases ownership so a queued scheduled monitor cannot be overtaken by the
next subnet target. There are no heap allocations or extra scan tasks for admission.
`-PR` requires local IPv4; `-Pn` bypasses discovery entirely.

Review fixes: per-port timeouts now span all resolved IP addresses; connect
and socket-option allocation errors are inconclusive; cancellation retains
safe late ICMP callback lifetimes; conflicting scan flags, empty quoted tokens,
malformed URL authorities and unsupported port syntax are rejected. The shared
command formatter accepts the same 32 KiB bounded reports as the scanner.
