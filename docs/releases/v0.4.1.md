# v0.4.1 — BLE measurement metrics and physical-limit alerts

## Changes since v0.4.0

- Ported the shared .NET decoder design to passive BLE monitoring: an immutable
  decoder registry, protocol admission filters, typed readings, per-protocol key
  validation and separate numeric samples and readable diagnostics.
- Added Victron instant-readout decoding for 13 supported record types: solar
  charger, battery monitor, inverter, DC/DC converter, SmartLithium, Inverter RS,
  AC charger, Battery Protect, Lynx BMS, Multi RS, VE.Bus, DC energy meter and
  Orion XS. The packet's record type selects the layout.
- Added Ruuvi RAWv2 (format 5) and BTHome v2 decoding. Ruuvi and plaintext BTHome
  need no key; Victron and encrypted BTHome use a 16-byte broadcast key. BTHome
  AES-CCM packets are authenticated before decoding.
- Added `--metric` selection across the supported protocols and their numeric
  and binary measurements, including repeated BTHome objects. Automatic v2
  scale/offset encoding matches .NET, supports signed physical values and
  reserves encoded 65535 for failure. Values such as negative battery current
  remain successful readings rather than timeout markers.
- Added endpoint label/unit/scale/offset metadata and physical high/low limits.
  Limits compare decoded physical values, so users enter volts, amps, degrees
  or the endpoint's displayed unit. Missing limits disable that direction;
  low must be less than high when both are set. Floating-point roundoff is
  tolerated; readings equal to a limit do not breach it.
- A physical breach records direction, value, limit, unit and observation time
  and uses the existing trigger-once-until-reset lifecycle. A successful probe
  can breach a limit without making the endpoint unavailable. Changing the
  endpoint/metric/limits clears a stale breach; reset clears the latched breach.
- Successful Nmap and BLE-listen durations use scale 10, matching .NET. Updated
  HTTPS expiry handling to classify expiry within seven days consistently.
- Stabilized probe status labels and kept changing measurements and diagnostic
  text separate, avoiding growth of the backend's shared status lookup.
- Refreshed the .NET fixture provenance to the current shared-library commit;
  the generated wire fixtures themselves are unchanged.

## BLE examples

Configure the host's Address with the device's actual BLE address. Set Args to:

```text
--format victron --metric battery_current
--format ruuvi --metric temperature
--format bthome --metric temperature
```

For Victron, set Password to the device's instant-readout AES broadcast key
from VictronConnect. For encrypted BTHome, use its configured AES key. This is
not a Bluetooth pairing PIN. Backend metadata resolves the selected metric's
unit and automatic scale/offset; users do not supply those encoding values.
The shared passive observer handles concurrent monitors without starting an
independent radio scan per host. Full listen diagnostics include raw captures,
decoded readings/errors and the end reason.

## Validation

- 33 native CTest targets passed with AddressSanitizer and UndefinedBehaviorSanitizer.
- Python tooling: 53 tests, one skipped, no failures.
- .NET contract oracle: eight fixture files verified and 113 deserialization
  assertions passed. Only the source-commit provenance changed.
- Clean checkout firmware build with pinned submodules and managed components;
  signed application verified with the existing OTA signing key. Live factory
  image generated from `firmware/config/appsettings-live.json` and checked for
  public configuration only.

The clean-build and artifact checks accompany this release. Earlier board tests
exercised these features during development; this release does not claim a new
physical RF stress test or exhaustive manufacturer/device coverage. No board
is flashed by publishing the release.

## Installation, compatibility and limitations

The release contains two distinct firmware downloads:

- **Signed application:** use for OTA on an enrolled ESP32-S3. Its application
  is environment-independent; OTA preserves the device's current Live/Dev
  configuration, Wi-Fi settings and enrollment. Do not upload the factory image
  through the website OTA flow.
- **Live factory image:** first installation on the tested ESP32-S3 with 16 MB
  flash and 8 MB octal PSRAM. It embeds the public `appsettings-live.json`
  profile and starts serial Wi-Fi setup and browser OAuth enrollment. Erase
  existing flash before first installation. This replaces device configuration;
  use OTA to update an enrolled device while retaining configuration.

Use the corresponding backend release with BLE metric metadata and physical
alert-limit support, including its database migration, before configuring these
features. Existing host settings can leave limits unset. Old stored readings
are not rewritten into the new BLE v2 encoding. The backend's optional threshold
fields and breach metadata follow the shared .NET contract.

BLE command processors remain unsupported on ESP32. Ruuvi supports RAWv2 only;
BTHome supports the documented v2 object catalogue. Victron GX/test records are
not admitted by live scanning, and Victron broadcast encryption does not provide
an authenticated integrity tag. Passive scanning cannot capture fields available
only through active scan responses. Existing bounded embedded OpenSSL/Nmap
adaptations and unsupported endpoints remain as documented.

Hardware Secure Boot and flash encryption remain disabled. Project sources are
GPL-3.0-only with separately licensed dependencies. Matching project source is
[the immutable v0.4.1 tag](https://github.com/Mungert69/NetworkMonitorProcessorAgentEmbedded/tree/v0.4.1).
Clone with `--recurse-submodules`: GitHub's automatic source archives omit the
submodule contents. Dependency revisions are pinned in submodules and
`firmware/dependencies.lock`; ESP-IDF revision and dependency license references
are in the attached `THIRD_PARTY_NOTICES.md` and CycloneDX SBOM. No private
signing key, Wi-Fi password, OAuth token or enrolled device state is distributed.
