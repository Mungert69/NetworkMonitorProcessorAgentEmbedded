# v0.5.3 — BLE memory limit and security testing

This release publishes the previously unreleased 0.5.3 security hardening. The
previous public release was v0.5.2.

## Security fix

- **Bound passive BLE history memory.** A nearby transmitter can produce many
  distinct advertisements. BLE history and immutable snapshots now share a
  1 MiB owned-memory budget. The processor checks the full prospective
  allocation before allocating and reserves space for snapshot publication.
  When the budget is reached, it rejects new captures, reports the incomplete
  scan, preserves existing history, and resumes accepting data as snapshots
  drain and expired entries are reclaimed. This addresses an availability risk;
  testing did not demonstrate code execution.
- **Enable strong stack protection.** The production compiler configuration now
  uses `-fstack-protector-strong` as additional defence in depth. Existing
  ESP-IDF memory protection and FreeRTOS stack-overflow checks remain enabled.

## Security testing

The security review tested the deployed configuration and exercised production
camera XML, RTSP, RTP/JPEG, BLE decoder, and MQTT command-dispatch paths. The
sanitizer-enabled native suite passed 44/44 tests. Mutation campaigns processed
approximately 19.6 million inputs or sessions under AddressSanitizer and
UndefinedBehaviorSanitizer without a reproducible memory-safety failure, crash,
or demonstrated exploit. The command-dispatch campaign uses a permissive crypto
test adapter, so it does not test signature verification. Fuzz harness sources
and rerun instructions are included in `tests/security/fuzz/`.

This is bounded test evidence, not proof that all inputs or dependencies are
safe. No physical-board fault injection, RF stress, long soak, Wi-Fi driver
fuzzing, or OTA rollback test was performed. The full scope and limitations are
in the [security test report](https://github.com/Mungert69/NetworkMonitorProcessorAgentEmbedded/blob/v0.5.3/docs/security-test-report-2026-11-12.md).

## Updating

Use the signed versioned `networkmonitor-esp32-s3-0.5.3-<sha256>.bin` for OTA
on an enrolled ESP32-S3. OTA retains enrollment, Wi-Fi settings, and monitor
configuration. The current firmware rejects reinstalling the version already
running. The live factory image is for first installation only; it replaces
device settings and requires Wi-Fi setup and enrollment. **Do not use the
factory image for OTA.** Verify downloads with `SHA256SUMS.txt`.
