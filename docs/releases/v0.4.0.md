# v0.4.0 — Embedded diagnostics and command processors

## Release contents

- Added an independently implemented Nmap-compatible TCP scanner and monitoring
  endpoint. Supports port lists/ranges, bounded IPv4 CIDR discovery, fresh local
  ARP discovery, state/reason output and common CLI switches. No Nmap source,
  libpcap, vulnerability scripts, raw SYN scans or OS fingerprinting.
- Added six command processors: QuantumCert, QuantumConnect,
  QuantumPortScanner, QuantumInfo, Openssl and Nmap, with signed MQTT command
  handling and paginated results.
- Added an OpenSSL-style adapter backed by wolfSSL: TLS 1.2/1.3, classical and
  ML-KEM groups, explicit AES-GCM cipher selection, SNI, ALPN, certificate
  identity verification and presented PEM chains. Unsupported commands fail
  explicitly; this is not the complete OpenSSL CLI.
- Added 5,889 updateable IANA TCP service-name hints. Labels describe registered
  ports, not detected service versions.
- Serialized shared ARP discovery with bounded FIFO admission. Queue/resource
  failures remain inconclusive rather than declaring a monitored host down.
- ESP32 devices identify themselves as `PType: "ESP32-S3"` during registration
  and ready reports. Firmware eligibility is based on device type and command
  protocol, independent of the ML-DSA/ES256 command-signing choice.
- Separated CLI parsing, command policies, typed runners and TLS provider I/O;
  expanded ownership, allocation-failure, cancellation and interoperability
  tests. Removed duplicate trust notes from OpenSSL certificate reports without
  changing QuantumCert trust reporting.

## Validation

The final feature build passed 32 native sanitizer tests, 42 adapter
interoperability cases, 54 quantum regression cases and 52 tooling tests.
IPv6 transport was skipped on the host lacking an IPv6 loopback address.
Real-board/frontend tests exercised Nmap, TLS 1.2/1.3, hybrid/standalone ML-KEM,
ALPN, identity verification, ML-DSA certificate inspection, PEM pagination and
strict rejection of untrusted certificates. Monitoring and application
acknowledgements continued with no observed allocation failures or disconnects.
These are bounded tests, not a long-duration leak or exhaustive CLI test.

## Installation and limitations

The Live factory image is for first installation on the tested ESP32-S3 with
16 MB flash and 8 MB octal PSRAM. It includes public Live settings, not Wi-Fi
passwords or account tokens. Erase the entire flash before first installation;
follow `docs/first-physical-board.md` for serial Wi-Fi setup and browser OAuth.
Use the separate signed application asset for website OTA updates, which
preserve configuration and state. Never use the factory image for OTA.

Hardware Secure Boot and flash encryption remain disabled. Protect physical
access and saved credentials. The project is GPL-3.0-only with separately
licensed dependencies. Matching source is the immutable v0.4.0 tag; clone with
`--recurse-submodules`. Dependency revisions are pinned in the submodules and
`firmware/dependencies.lock`. See the attached notices and CycloneDX SBOM.

Full adapter coverage: `docs/openssl-adapter.md`.
Scanner limitations: `docs/nmap-endpoint-port-notes.md`.
